# 수련 원본 → 검사·변환 → 배포 결과

- 결정일은 2026-09-23이며, 이 문서는 배포 경로 설계 0.1이다.
- 검토 기준은 커밋 `33915f4a3a5bdb3ac9388c654c244d313e31e815`이다.
- 이번 완료 범위는 경계·디렉터리·변환 책임·이행 순서를 정하고 원본/화면 폴더 안내를 만드는 것이다. 실제 데이터, 변환기, 배포 작업 흐름은 아직 옮기거나 구현하지 않는다.

## 1. 결정과 기존 문서의 관계

**수련 데이터는 검토·교정하는 원본이고, 배포 데이터는 그 원본에서 프로그램이 생성하는 읽기용 결과물이다.** 두 형식은 다르지만, 사람이 편집하는 수련 내용의 기준은 하나다.

[동작·상태 데이터 모델](data-model.md)은 수련 원본의 의미와 구조를 정한다. [좌표계 원칙](coordinate-system.md)은 좌표·지지·접촉·상태/사건의 의미를 정한다. 이 문서는 그 정보를 언제 검사하고 어떻게 화면에 전달하는지를 보완한다. 기존 문서의 UI 조합 규칙 중 참조 해석·해설 범위 선택·표시 자격 검사는 배포 전 변환기의 책임으로 구체화한다. 상태·동작·해석의 구분은 바꾸지 않는다.

원자료를 읽고 해석하는 일은 작성 단계에서 한다. 배포할 때 AI나 외부 웹페이지를 다시 호출해 동작을 재해석하지 않는다. 자동 검사 통과는 내용의 진위나 실제 수련 적합성을 보증하지 않는다.

## 2. 디렉터리와 편집권

아래는 이행 후의 목표 구조다. 이번에는 `training/README.md`, `web/README.md`와 생성물 제외 규칙만 추가한다. 나머지 파일은 구현할 때 만든다.

```text
eztaiji/
├── training/                      # 사람이 검토하고 고치는 수련 원본이다.
│   ├── README.md
│   ├── notes/                     # 공개 가능한 작업 메모이며 자동 입력에서 제외한다.
│   └── datasets/
│       └── yijian.json             # 첫 버전의 기준 Dataset 한 벌이다.
├── web/                           # 사람이 고치는 화면 코드와 정적 자산이다.
│   ├── README.md
│   ├── index.html
│   ├── about.html
│   └── assets/
├── schemas/                       # 두 데이터 형식의 실행 가능한 규격을 둔다.
│   ├── training.schema.json
│   └── deployment.schema.json
├── scripts/                       # 로컬과 자동 배포가 공유할 도구를 둔다.
│   └── build.mjs
├── tests/                         # 검사·변환·화면의 시험을 둔다.
│   └── fixtures/                  # 가상 예시이며 실제 수련 입력으로 읽지 않는다.
├── docs/                          # 설계와 진행 기록을 둔다.
├── .build/                        # 임시 결과와 검사 보고서이며 Git에서 제외한다.
├── dist/                          # 성공한 빌드의 사이트 전체이며 Git에서 제외한다.
│   ├── index.html
│   ├── about.html
│   ├── assets/
│   └── data/
│       └── taiji-data.js           # 자동 생성하는 배포 데이터다.
└── .github/workflows/pages.yml     # 구현 후 dist만 배포하도록 연결한다.
```

| 위치 | 사람이 수정하는가? | 배포 대상인가? | 책임 |
| --- | --- | --- | --- |
| `training/datasets/` | 그렇다. | 원본 그대로는 아니다. | 수련 내용과 근거의 기준이다. |
| `training/notes/` | 그렇다. | 아니다. | 정리 전 메모이며 채택한 내용만 기준 Dataset에 반영한다. |
| `web/` | 그렇다. | 허용된 화면 파일만 복사한다. | 수련 내용을 중복 저장하지 않는다. |
| `schemas/`, `scripts/`, `tests/`, `docs/` | 그렇다. | 아니다. | 검사·변환·개발의 자료다. |
| `.build/` | 아니다. | 아니다. | 임시 결과와 작성자용 진단을 둔다. |
| `dist/` | 아니다. | 그렇다. | 지우고 다시 만들 수 있는 결과물이다. |

이행 완료 후 발 좌표나 설명을 고칠 곳은 `training/`뿐이다. 화면 배치·색·스크롤은 `web/`에서 고친다. `dist/`를 손으로 고쳐 원본 대신 사용하는 일은 금지한다. 원본이 누락되었을 때 이전 배포본을 입력으로 삼지도 않는다.

초기에는 논리적 Dataset을 JSON 한 파일에 둔다. 자세별 파일 분할이 필요해지면 저장 방식만 바꾸고, 조합된 Dataset 계약은 유지한다. 지금 파일 분할 규격까지 새로 만드는 것은 보류한다. 기준 데이터셋 안에 Sources를 두며 별도의 출처 사본을 동시에 편집하지 않는다.

빌드는 명시적으로 지정한 `training/datasets/yijian.json`만 읽는다. `training/` 전체를 검색해 메모·예시·임시 파일까지 자동 채택하지 않는다. 미등록 동작 슬롯과 `unknown` 값은 원본 모델의 규칙대로 둔다.

## 3. 공개 범위는 폴더 경계와 별개다

2026-09-23에 저장소 메타데이터의 `private:false`와 `visibility:public`을 확인했다. `dist`에서 제외한다는 것은 웹앱 배포물에 넣지 않는다는 뜻이지, 공개 저장소의 원본을 비공개로 만든다는 뜻이 아니다.

따라서 공개하면 안 되는 수련 메모·개인정보는 이 저장소 바깥에 둔다. `training/notes/` 역시 공개 가능한 메모만 커밋한다. 이행 전에는 루트에서 사이트 파일을 제공하는 기존 구조가 남아 있으므로, 아직 `dist`만 배포한다는 보장이 있다고 말하지 않는다. Pages 설정은 이번 작업에서 변경하지 않는다.

배포물은 제외 목록에 의존해 저장소 전체를 복사하지 않는다. `web/`의 지정된 HTML·자산과 생성 데이터만 허용 목록으로 선택한다. README, 수련 원본, 시험 예시, 검사 보고서, 원문 사본은 포함하지 않는다.

## 4. 원본 모델과 배포 모델

원본은 `State`, `Motion`, `Interpretation`, `Source`, 필드별 `Claim`을 보존한다. 배포본은 브라우저에서 필요한 값을 직접 찾을 수 있게 연결한다. 서로 다른 규격이므로 `training.schema.json`과 `deployment.schema.json`을 따로 검사한다. 원본 스키마 버전과 배포 형식 버전도 독립적으로 둔다.

배포본의 목표 구성은 다음과 같다. 이는 실행 가능한 스키마가 아니라 다음 구현 단계의 계약이다.

```text
DeploymentData
  formatVersion
  meta
    datasetId, datasetRevision
    trainingSchemaVersion, generatorVersion, inputDigest
  catalog                        # 단·자세·번호·목차를 가진다.
  navigation                     # 시작/동작 화면의 순서와 이전·다음을 가진다.
  states                         # 화면용 상태를 ID로 찾는다.
  views                          # 화면 문맥과 필요한 ID를 미리 연결한다.
  interpretations                # 공개할 해설과 적용 범위를 가진다.
  sources                        # 공개할 근거 표기만 가진다.
```

배포 상태에도 평면 좌표와 질적 방향·영역을 남긴다. 픽셀 위치·화면 폭·스크롤 위치는 넣지 않는다. 값뿐 아니라 `unknown`, 근거 유형, 근사 여부, 해석의 한계와 공개 근거 참조를 보존한다. UI가 기호를 표시해도 되는지에 관한 판단 결과를 미리 붙일 수 있지만, 그 판단이 자료의 확실도를 높이지는 않는다.

`views`는 화면 ID별로 자세·동작·시작/결과/중간 상태의 ID, 안내, 확인 사항, 관련 해설과 근거 ID를 가진다. `previousEnd`의 복잡한 참조는 빌드에서 해석하고 브라우저에는 바로 조회할 ID를 전달한다. 브라우저의 단순 ID 조회까지 없애기 위해 상태 전체를 매 화면에 복제할 필요는 없다.

예를 들어 앞 자세의 마지막 화면과 다음 자세의 시작 화면은 같은 `stateId`를 사용하되, 안내와 해석은 별도다. 다음 시작 화면의 사건 목록은 비어 있으므로 이전 동작의 `Heel ↑`를 다시 재생하지 않는다. 시작 상태를 제공할 결과가 미등록이면 명시적인 미등록 상태를 내보낸다.

범위가 여러 동작에 걸친 해설은 배포본에도 한 번 저장한다. 관련 화면은 그 해설 ID와 ‘左掤 전체’ 또는 ‘1–3동작’ 같은 범위를 참조한다. 같은 문단을 동작별로 다시 작성하지 않는다.

## 5. 무엇을 변환하고 무엇을 보존하는가

| 입력 | 빌드가 할 일 | 하지 않을 일 |
| --- | --- | --- |
| 다음 자세의 `previousEnd` | 유효한 직전 결과의 상태 ID를 찾는다. | 비슷한 다른 상태로 공백을 메우지 않는다. |
| `C = 오른발 쪽` | 질적 영역과 그 표기를 유지한다. | 화면을 채우려고 `x=0.87`을 만들지 않는다. |
| 근사 좌표 또는 추론 | 해당 표시와 공개 근거를 보존한다. | 측정값·확정 사실로 바꾸지 않는다. |
| 접촉 기호의 근거 | 기호 허용 여부와 이유를 규칙으로 정한다. | 추론을 확인된 Toe/Heel 기호로 승격하지 않는다. |
| 동작 묶음의 음양·전투 해석 | 범위를 검증하고 관련 화면에 연결한다. | 매 동작의 고유 용법으로 분해하지 않는다. |
| 근거 충돌 | 미확인/충돌 표시와 필요한 공개 설명을 유지한다. | 마지막 입력값을 자동 정답으로 삼지 않는다. |
| 작업 메모와 원문 사본 | 배포 입력으로 읽거나 복사하지 않는다. | 배포 때 AI가 요약해 사실을 새로 만들지 않는다. |

공개 Source는 ID, 공개 가능한 제목·URL·자료 위치 설명으로 제한한다. 원문 전체, 내부 파일 경로, 불필요한 인물 정보는 자동 복사하지 않는다. URL이 없는 수련 기록도 실제 근거의 성격을 왜곡하지 않는 공개 설명으로 표기할 수 있다. 그 설명은 사람이 작성하며 변환기가 발명하지 않는다.

필드가 추가되어도 기본적으로 배포 필드에 포함하지 않는다. 허용 목록을 명시적으로 갱신한다. 다만 정보의 한계를 설명하는 문구까지 지워서는 안 된다. 공개 가능한 대체 설명이 없어서 주장이 과장되거나 근거가 사라진다면 해당 내용의 공개 방식을 수정할 때까지 빌드를 막는다.

## 6. 검사·변환 명령의 책임

목표 명령은 `node scripts/build.mjs` 한 개다. 아직 파일을 만들거나 이 명령을 실행한 상태가 아니다. 로컬과 자동 배포가 같은 구현을 실행하도록 한다.

처리 순서는 다음과 같다.

1. 명시한 수련 원본과 화면 파일을 읽고 지원하는 버전을 확인한다.
2. 원본 형식과 필드 제약을 검사한다.
3. ID·소속·시작 상태·묶음 범위·사건 선후·근거 참조를 검사한다.
4. 읽기 전용 원본에서 배포 모델을 생성한다. 원본 파일이나 원본 객체를 변경하지 않는다.
5. 배포 모델의 형식과 모든 참조, 불확실성 보존, 공개 필드 규칙을 다시 검사한다.
6. `.build/`의 새 작업 폴더에 화면과 데이터를 조립하고 파일·상대 경로·초기 로딩을 검사한다.
7. 성공한 사이트 후보만 `dist/`로 승격한다. 검사 보고서는 `.build/`에 둔다.

실패 시 종료 코드는 실패를 나타내고, 어느 입력 파일·레코드·필드에서 어떤 규칙이 깨졌는지 보고한다. 읽을 수 있는 진단의 예는 ‘p002 시작 상태가 직전 자세가 아닌 p010을 참조함’이다. 조용히 값을 고친 뒤 성공으로 끝내지 않는다.

구조 오류, 깨진 참조, source/observation의 필수 근거 누락은 오류다. 올바르게 기록한 `unknown`, 결과 상태 미등록, 아직 없는 전투 해설은 자료 공백이며 허용한다. 위험하지 않은 작성 알림은 경고로, 정상 미등록은 정보로 구분한다. 단순 공백을 수백 개의 오류처럼 쏟아내지 않는다.

이전 `dist/`가 로컬에 남아 있어도 실패한 빌드가 그것을 새 결과로 업로드해서는 안 된다. 자동 배포는 이번 실행에서 성공한 후보만 사용한다. 빌드 실패 때문에 기존에 공개된 사이트를 빈 사이트로 덮어쓰지 않는다.

## 7. 재생성과 브라우저의 경계

같은 원본·화면 코드·생성기 버전·고정된 실행 환경에서는 같은 배포 파일을 만들도록 한다. 현재 시간, 난수, 실시간 웹 응답을 생성 데이터에 넣지 않는다. 내용 해시와 버전은 데이터에, 실행 시각과 작업 로그는 별도 보고서에 둔다. 스크립트·의존성을 사용할 경우 환경과 버전을 고정하는 일도 구현 체크에 포함한다.

배포 데이터는 JSON으로 표현 가능한 값이다. 첫 버전에서는 기존 ‘HTML 파일 직접 열기’를 보존하는 것을 목표로, 자동 생성한 일반 스크립트 `data/taiji-data.js`로 전달한다. 스크립트는 데이터 초기화만 하며 원본의 임의 코드를 실행하지 않는다. 임의 문자열을 코드 템플릿에 직접 삽입하지 않고 안전하게 직렬화한다. 별도 JSON 파일을 손으로 병행 편집하지 않는다.

이 전달 방식의 실제 동작은 `file://`와 HTTP 양쪽에서 시험한다. 아직 시험하지 않았으므로 직접 열기 호환성을 완료 처리하지 않는다. HTML에서는 `./data/taiji-data.js`처럼 상대 경로를 사용해 `/eztaiji/` 하위 경로에서도 확인한다. 로딩 순서와 버전 불일치·누락 파일 안내도 검사 대상이다.

브라우저에는 화면 선택, 단순 ID 조회, 확대·축소와 픽셀 변환, 접힘·스크롤, 미등록 안내, 로딩/형식 불일치의 최소 방어 처리를 남긴다. 전체 원본 스키마나 근거망을 매번 재검증하는 도구는 보내지 않는다. 화면은 HTML 삽입이 아니라 안전한 텍스트 표시를 기본으로 한다.

## 8. 배포 경로와 이전 방식에서의 전환

목표는 GitHub Actions에서 검사·빌드·기본 화면 시험을 통과한 `dist/`만 Pages 결과물로 업로드하는 것이다. 배포 작업은 성공한 빌드 작업에 의존해야 한다. PR에서는 검사와 미리보기 결과만 만들고, 승인된 main 경로에서만 운영 배포한다. 오래된 실행이 새 실행 뒤에 배포되지 않도록 배포 동시 실행도 제어한다.

GitHub 공식 문서는 사용자 지정 작업 흐름의 빌드 결과 업로드와 배포 작업 연결을 설명한다. Pages의 브랜치 게시와 Actions 게시 설정도 별도다. 따라서 검사 파일을 추가하는 것만으로 배포 차단이 완성되었다고 보지 않는다. 이행 시 실제 Pages 게시 소스와 작업 의존성을 확인하고 전환해야 한다.

지금 루트의 `index.html`, `about.html`, `catalog.js`, `.nojekyll`은 유지한다. 새 경로를 검증하기 전에 옮기지 않는다. 실제 이행 시 다음 순서를 따른다.

1. 두 실행 스키마와 최소 입출력 예시를 만든다.
2. 검사·변환기를 만들고 가상 데이터로 실패·성공 조건을 시험한다.
3. 예비식의 수련 원본을 만들고 기존 값의 의미를 대조한다.
4. 작업 브랜치에서 화면을 `web/`로 옮기고 동작 데이터를 화면 코드에서 제거한다. `catalog.js`의 목차도 원본에서 생성하며 두 목차를 따로 관리하지 않는다.
5. 로컬 `dist`에서 시작 상태, 부분 미등록, 해석 범위, 직접 열기, 작은 화면을 확인한다.
6. 실제 Pages 게시 소스를 Actions로 전환하고 성공한 결과물만 배포되는지 확인한다.
7. 새 경로의 동작을 확인한 뒤 이전 루트 파일과 중복 데이터 제거를 마무리한다.

처음부터 두 경로를 장기간 병행 운영하거나 원본을 배포본으로 역변환하는 기능은 만들지 않는다. 롤백 시에도 이전의 검증된 원본·코드 조합에서 다시 만들거나 그 조합의 검증된 결과물을 사용한다.

## 9. 구현 완료 판정

다음은 구현할 때 통과해야 할 기준이며, 이번에 실행한 시험 목록이 아니다.

- 정상 입력에서 dist가 생성되고 원본 파일은 바뀌지 않아야 한다.
- 깨진 참조·모순된 Claim은 빌드를 실패시키되 올바른 미등록은 허용해야 한다.
- 시작 상태는 같은 상태를 참조하면서 이전 사건을 재생하지 않아야 한다.
- 근사·추론·충돌·전투 가정의 한계가 배포 뒤에도 남아야 한다.
- 묶음 해설의 범위와 동작 수가 변환 전후 일치해야 한다.
- 원문·메모·내부 경로·원본 Dataset·시험 자료가 dist에 포함되지 않아야 한다.
- 생성물을 지운 뒤 재생성한 결과가 같은 입력의 이전 생성물과 일치해야 한다.
- 실패한 실행은 남아 있는 이전 dist를 새 배포물로 사용하지 않아야 한다.
- file://, HTTP, /eztaiji/ 경로, 모바일 화면의 기본 사용과 실패 안내가 작동해야 한다.
- 실제 게시 설정이 검사 성공 경로에 연결되어 있어야 한다.
