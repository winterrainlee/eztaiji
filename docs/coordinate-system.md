# eztaiji 동작 좌표계 원칙

- 문서 버전: 1.4
- 문서 정합성 갱신일: 2026-09-23
- 용도: 태극권 초식의 무게중심·발·팔 구조를 이해하기 쉽게 기록하고 웹앱에서 시각화하기 위한 공통 규칙
- 표기 성격: 易簡太極拳의 공식 용어 체계가 아니라, 동작의 공간 관계를 이해하기 위해 만든 프로젝트 학습 표기법
- 적용 범위: [동작·상태 데이터 모델 0.1](data-model.md)과 문서의 정의를 맞췄다. 기존 예비식 데이터, 렌더러, 시작 상태 UI는 아직 이행하지 않았다.

## 1. 목적과 적용 범위

이 좌표계는 자세의 모양만 외우지 않고, **무게중심 C, 두 발의 위치·허실·방향, 두 팔의 최종 구조 방향**을 한눈에 읽기 위해 사용한다. 좌표판은 ‘현재 자세가 어떻게 생겼는가’를 우선한다. 몸통·고관절·허리·어깨·팔꿈치가 그 자세를 어떻게 만들었는지는 상태와 동작 데이터에 남기고 좌표판에 모두 그리지 않는다.

실제 자세와 동작 순서는 사부님의 지도와 해당 易簡太極拳 자료를 우선한다. 관찰·자료의 기술, 프로젝트의 추론, 학습용 예시를 구분한다. 확인되지 않은 중간 동작을 사실처럼 보간하지 않는다.

몸의 상태, 상태 사이의 변화, 원리·음양·전투 가정, 화면 표현은 서로 다른 정보다. 이 문서는 공간 표기의 의미를 정하고, 저장 구조와 참조·근거 형식은 `data-model.md`를 따른다. 문서를 맞췄다는 사실은 실제 동작이나 프로그램의 검증을 뜻하지 않는다.

## 2. 좌표 기준

### 2.1 보는 방향과 고정 축

수련자를 위에서 내려다본 바닥 평면을 사용한다. 축은 太極起勢가 끝난 기준 시점에 고정한다. 몸이 회전해도 축은 따라 돌지 않는다.

| 표기 | 의미 |
| --- | --- |
| `+x` | 기준 시점에 수련자의 오른쪽이었던 방향이다. |
| `−x` | 기준 시점에 수련자의 왼쪽이었던 방향이다. |
| `+y` | 기준 시점에 수련자가 바라보던 정면이다. |
| `−y` | 그 기준 정면의 뒤쪽이다. |

`leftFoot/rightFoot`는 수련자 몸의 왼발·오른발이다. 화면에서 왼쪽에 있는 발을 항상 왼발이라고 부르거나, 몸이 돈 뒤의 현재 오른쪽을 `+x`로 다시 정의하지 않는다. 동작 설명에 쓰는 ‘앞·뒤·좌·우’도 몸 기준인지 고정 좌표 기준인지 혼동할 수 있으면 명시한다.

기존 설명에서 쓴 東·北은 축을 기억하기 위한 이름일 뿐 실제 나침반 방향이 아니다. 평면의 `y`는 전후 방향이며 몸이나 발의 높이가 아니다.

### 2.2 원점과 발 위치의 기준점

기본 원점은 太極起勢가 끝났을 때의 왼발 기준점이다. 같은 좌표계로 기록하는 동안에는 자세나 단이 바뀌어도 원점을 옮기지 않는다.

| 발 | 기준 좌표 | 기존 학습 기준의 허실 |
| --- | --- | --- |
| 왼발 | `(0, 0)`이다. | `● 實`로 기록해 왔다. |
| 오른발 | `(1, 0)`이다. | `○ 虛`로 기록해 왔다. |

표의 허실은 기존 프로젝트의 학습 기준이며 원점이나 좌표로부터 계산한 결과가 아니다. 실제 데이터에서는 해당 시점의 근거와 함께 독립적으로 기록한다. 다른 시점이나 미확인 상태에 이 허실을 기본값으로 복사하지 않는다.

발 좌표는 **발 형태의 중심을 바닥 평면에 투영한 학습용 기준점**을 뜻한다. 발이 닿아 있거나 떠 있는 경우 모두 같은 종류의 기준점을 사용한다. 접촉 부위가 달라졌다는 이유만으로 좌표점을 그 부위로 바꾸지 않는다.

이 점은 발바닥 접촉면의 가운데, 발끝, 뒤꿈치, 압력이 모이는 점, 회전축을 뜻하지 않는다. 1.2의 ‘접촉면 가운데’ 정의를 이번 버전에서 바꿨다. 이전 값은 근사 도해의 값이므로 새 기준점의 실측값으로 자동 변환하지 않는다.

별도 분석에서 좌표계를 다시 잡아야 한다면 새 `coordinateFrameId`와 기준 설명을 둔다. 다른 좌표계의 상태를 같은 값인 것처럼 직접 비교하거나 이어 그리지 않는다. 화면 확대·이동만 필요하다면 새 좌표계가 아니라 화면 변환을 사용한다.

### 2.3 격자 단위

기준 자세의 양발 간격을 `1`로 하는 학습용 근사 단위를 사용한다. 센티미터나 개인별 실제 보폭의 측정값이 아니다. 분명한 한 걸음을 보통 `1`로 나타내던 프로젝트의 단순화는 유지하되, 모든 걸음이 반드시 같은 길이라는 규칙으로 강제하지 않는다.

작은 발 정렬이나 이동은 근거와 필요에 따라 `0.2`~`0.4` 같은 소수로 나타낼 수 있다. 소수점이 있다는 이유로 측정값이 되지 않으며, 발 방향만 바뀌었다고 반드시 소수 좌표 이동을 추가하지 않는다.

연속 좌표를 허용한다. 상대 위치조차 확인되지 않았다면 격자에 맞추려고 값을 만들어 넣지 않는다. 좌표의 미확인과 학습용 근사값을 구분한다.

## 3. 발의 허실과 중심

| 표기 | 의미 |
| --- | --- |
| `● 實` | 현재 몸을 주로 받치는 지지 역할을 나타낸다. |
| `○ 虛` | 지지를 덜어 이동이나 방향 전환을 준비하는 역할을 나타낸다. |
| `shared` | 이 앱에서 양발이 함께 지지함을 기록하는 값이다. |
| `C` | 몸의 질량중심을 바닥에 투영한 학습용 위치 또는 영역을 나타낸다. |

허실은 양발별로 독립 기록한다. 한 발을 實로 기록했다고 다른 발을 자동으로 虛로 만들지 않는다. `shared`는 앱의 설명용 값이며, 체중 50:50이나 전통 이론의 ‘雙重’ 판정을 뜻하지 않는다. 허실이 미확인이면 ●/○ 중 하나로 대신 표시하지 않는다.

C와 발의 지지 역할 역시 독립된 정보다. ‘오른발이 지지한다’는 기록만으로 C의 좌표나 양발 체중 비율을 계산하지 않는다. C를 발바닥 압력이나 지면 반력을 표시하는 값으로 사용하지 않는다.

C는 근거가 있는 경우 점 좌표로, ‘오른발 쪽’ 정도만 확인되면 영역으로 기록한다. 영역의 `leftFoot/rightFoot/betweenFeet`는 발과의 관계이고, `front/back`은 이 좌표계의 기준 정면·뒤쪽이다. 질적 영역을 임의의 정밀한 점으로 바꾸지 않는다. C의 이동 방향은 현재 상태의 위치와 구분해 동작의 변화에 기록한다.

발이 새 자리에 닿은 것과 그 발이 주된 지지를 맡는 것은 구분해 읽는다. 발 위치·허실·접촉·C 가운데 한 항목을 안다는 이유로 다른 항목을 채우지 않는다.

### 3.1 발 접촉 상태와 접촉 변화

| 표기·정보 | 기록할 위치와 의미 |
| --- | --- |
| `Toe` | 상태의 확인된 발끝 접촉을 표시한다. |
| `Heel` | 상태의 확인된 뒤꿈치 접촉을 표시한다. |
| 뒤꿈치가 들려 있다. | 상태의 `heelRaised`에 기록한다. |
| `Heel ↑` | 해당 동작에서 뒤꿈치를 드는 사건을 표시한다. |
| `Heel ↓` | 해당 동작에서 뒤꿈치를 내리는 사건을 표시한다. |
| `groundContact: none` | 확인된 비접촉 상태이며 미확인과 다르다. |

`Heel ↑/↓`의 화살표는 높이의 변화이며 평면의 `+y/−y` 이동이 아니다. 뒤꿈치 내리기는 뒤꿈치부터 새로 착지한다는 뜻과 구분한다. 현재 접촉과 접촉의 시작·종료도 같은 항목으로 저장하지 않는다.

접촉·들기·내리기 기호는 해당 내용이 명시된 자료 또는 관찰 기록을 근거로 표시한다. 데이터 모델의 `source/observation`과 명시적 근거 위치를 함께 기록한다. 해석은 해설에 남길 수 있지만 확인된 접촉 기호로 자동 변환하지 않는다.

허실, 발끝 방향, 좌표, 뒤꿈치 들림 중 하나만으로 접촉 부위나 회전축을 추정하지 않는다. 근거가 없으면 미확인으로 남긴다. 발 좌표를 접촉점이나 회전축에 대한 증거로 사용하지 않는다.

## 4. 몸 방향과 회전

몸 방향 `B`(Body)는 몸통의 현재 대표 방향을 기록한다. 발끝 방향과 독립된 상태 정보다. 골반·허리·팔의 연결은 해당 동작의 설명에 기록하며, 서로 다른 부위의 방향을 확인하지 못한 채 하나의 정밀한 각도로 단정하지 않는다.

기준 정면 `+y`를 `0°`로 둔다. 위에서 본 고정 평면에서 `+y`에서 `+x`로 도는 시계 방향을 양수로 정한다. 몸이 돌아도 이 부호 규칙은 유지한다.

| 방향 표시 | 각도 기준 | 방향 표시 | 각도 기준 |
| --- | ---: | --- | ---: |
| `↑` | `0°`이다. | `↓` | `180°`이다. |
| `↗` | `45°`이다. | `↙` | `225°` 또는 `−135°`이다. |
| `→` | `90°`이다. | `←` | `270°` 또는 `−90°`이다. |
| `↘` | `135°`이다. | `↖` | `315°` 또는 `−45°`이다. |

표는 각도를 읽는 기준이지 모든 방향 기록을 정확한 각도로 바꾸라는 뜻이 아니다. 대략적인 방향은 `sector`, 수치로 기록할 근거가 있으면 `angle`로 구분한다. 화살표를 화면에 그리기 위한 대표 각도를 실제 동작의 측정값으로 저장하지 않는다.

`B`와 발끝 방향은 상태에 둔다. 회전 방향·회전량 `ΔB`·경로는 동작의 사건에 둔다. 현재 방향은 이전 화면이 무엇이든 같지만, 얼마나 돌았는지는 어느 구간을 설명하는가에 따라 달라지기 때문이다.

끝점의 각도 차이만으로 실제 회전 방향·횟수·경로를 결정하지 않는다. 같은 방향으로 시작하고 끝나도 그 사이에 회전이 없었다고 단정할 수 없으므로, 확인되지 않은 변화에는 자동 회전 화살표를 만들지 않는다.

### 4.1 팔의 상대 방향과 좌표판 방향

팔은 고정 좌표계의 절대 방향을 원본 상태에 바로 저장하지 않는다. `State.arms.left/right.relativeDirection`에는 **현재 몸통 방향 B를 기준으로 한 팔 구조의 상대 주방향**을 기록한다. `front`는 몸 정면, `right`는 몸 오른쪽이라는 뜻이다. 이 값은 손바닥 면, 손끝의 순간 이동 경로, 힘의 벡터를 뜻하지 않는다.

좌표판의 빨간 팔 화살표는 다음처럼 계산한 최종 표시다.

`팔의 좌표판 방향 = B의 고정 좌표 방향 + relativeDirection`

따라서 몸이 회전하면서 팔이 몸과의 관계를 유지한 채 따라가면 `relativeDirection`은 그대로이고 빨간 화살표만 B와 함께 돈다. 반대로 B가 그대로인데 어깨·팔꿈치·팔의 관계가 바뀌면 `relativeDirection`이 바뀐다. 둘이 동시에 바뀔 수도 있다.

몸통·고관절·허리·어깨·팔꿈치의 연결 과정은 `configuration`, `Motion.events`, 동작 안내와 해석에 기록한다. 좌표판은 이 연결 사슬 전체를 선으로 그리지 않고, 수련자가 자세를 잡을 때 우선 확인하는 **C·발·팔의 결과 상태**만 요약한다. B는 팔 방향 계산과 상세 설명을 위한 데이터로 유지하지만 기본 좌표판의 독립 화살표로는 표시하지 않는다.

회전 설명을 무릎을 억지로 비트는 지시로 쓰지 않는다. 고관절·골반·허리의 역할과 지지발·발끝의 관계는 동작별 자료와 사부님 지도에 맞춰 기록한다. 발의 위치나 방향만으로 실제 회전축을 정하지 않는다.

## 5. 동작을 시간 순서로 기록하는 원칙

좌표 한 장은 한 순간의 상태다. 번호가 붙은 동작은 그 상태로 가는 변화이며, 두 개념을 같은 것으로 취급하지 않는다. 기본 분석 질문은 다음과 같다.

1. 어느 발이 지지를 맡고 있으며 무엇이 아직 미확인인지 확인한다.
2. 움직이는 발의 지지 역할이 어떻게 바뀌는지 살핀다.
3. 발 위치 변화와 접촉 변화를 나누어 기록한다.
4. C의 이동과 지지 전환을 각각 확인한다.
5. 몸 방향 B, 확인된 회전 사건, 팔의 역할이 어떻게 이어지는지 기록한다.

이것은 분석 질문의 순서이지 모든 초식의 실제 시간 순서가 아니다. 발 이동·지지 전환·몸 회전이 어떤 순서로 또는 함께 일어나는지는 확인된 근거를 따른다. 사건 배열 순서만으로 선후 관계를 만들지 않는다.

한 동작 안에 필요한 경우 확인된 중간 상태를 둔다. 중간 상태는 원자료의 동작 번호를 늘리지 않는다. 기본 좌표판은 해당 번호 동작의 결과 상태를 보여주고, 중간 과정은 같은 동작 안에서 별도로 펼칠 수 있도록 설계한다.

출발·결과 상태만으로 중간 경로, 소요 시간, 동시성을 만들어내지 않는다. 상태에서 빠진 항목도 이전 상태의 값으로 자동 상속하지 않는다. 같은 상태를 명시적으로 참조하는 일과, 다른 시점의 미확인 값을 이전 값으로 채우는 일은 다르다.

### 5.1 시작 상태와 자세 간 연결

각 자세에는 1동작에 들어가기 직전의 **시작 상태**를 둔다. 새 동작 번호가 아니므로 `0동작`이라고 표시하거나 전체 동작 수에 더하지 않는다.

같은 수련 기록과 좌표계에서 다음 자세의 시작 상태는 바로 앞 자세의 마지막 동작 결과 상태를 참조한다. 원본 상태를 공유하되 다음 자세의 소개와 해석은 새 문맥에서 선택한다. 이전 동작의 `Heel ↑/↓`나 회전 사건을 시작 상태에서 다시 표시하지 않는다.

참조할 마지막 상태가 미등록이면 시작 상태도 미등록으로 남긴다. 가장 가까운 등록 상태로 대신하지 않는다. 존재하지 않는 ID를 가리키거나 순환하는 참조는 정상적인 미등록과 구분해 데이터 오류로 다룬다.

첫 자세 預備式만 `권가 시작 전 상태`를 별도로 둔다. 이전 자세가 없다는 이유로 허실이나 좌표를 임의로 정하지 않는다. 1동작의 결과나 권가 마지막 상태를 초기 상태로 복사하지 않는다.

시간 흐름은 `시작 상태 → 1동작 → 1동작 결과 상태 → 2동작 → … → 마지막 동작 결과 상태`로 읽는다. 이 흐름은 설명용 개념이며, UI에서는 동작 안내와 그 결과 상태를 같은 화면에 보여준다. 별도의 결과 화면을 매번 한 장 더 만들라는 뜻이 아니다.

현재 합의한 탐색은 `시작 상태 → 1동작 → … → 마지막 동작 → 다음 자세 시작 상태`이다. 시작 상태와 중간 상태는 현재 목차의 64자세·365동작에 추가하지 않는다. 실제 탐색 규칙과 구현 상태는 [단·자세·동작 문서](routine-navigation.md)를 함께 확인한다.

## 6. 한 화면을 구성하는 정보의 기록 위치

| 정보 | 기록할 위치 |
| --- | --- |
| 발 위치·발끝 방향·발별 지지 역할·현재 접촉 | `State.feet`에 각 발을 독립적으로 기록한다. |
| 현재 중심 C | `State.center`에 점 또는 영역으로 기록한다. |
| 현재 몸 방향 B | `State.body`에 기록한다. 좌표판의 팔 방향 합성에 사용하며 기본 좌표판에는 독립 화살표로 그리지 않는다. |
| 손·팔의 현재 상대 배치 | `State.arms.configuration`에 질적 설명으로 기록한다. |
| 몸 기준 팔 구조 방향 | `State.arms.relativeDirection`에 기록하고, 좌표판의 빨간 화살표는 B와 합성해 계산한다. |
| 발 이동·들기·내리기·중심 이동·회전 ΔB | `Motion.events`에 변화로 기록한다. |
| 확인된 선후·겹침 관계 | `Motion.eventRelations`에 기록한다. |
| 동작 안내·자기 점검 | 해당 `Motion`의 설명에 기록한다. |
| 원리·음양·전투 가정 | 범위를 가진 `Interpretation`으로 기록한다. |
| 출처·관찰·추론·근사 여부 | 각 정보의 `Claim`과 근거 참조에 기록한다. |

확실도는 화면 전체가 아니라 정보별로 다를 수 있다. 접촉은 자료에 명시되어 있고 좌표는 학습용 근사이며 C는 미확인인 상태를 그대로 표현한다. 실제 사부님 설명, 자료의 기술, 직접 관찰, 추론, 학습용 예시의 근거를 섞지 않는다.

물리 항목의 미확인은 `unknown`, 그 항목이 적용되지 않는 경우는 이유가 있는 `not_applicable`로 구분한다. 아직 없는 결과 상태의 참조는 `null`로 나타낸다. `0°`, `(0,0)`, 빈 문자열을 미확인 대용으로 사용하지 않는다.

학습용 근사값에는 `illustration` 등 실제 근거 성격과 `approximate`를 남긴다. `known`은 값이 기록되었다는 뜻이지 실연을 검증했다는 뜻이 아니다. 자료가 충돌하면 각 근거와 대안을 보존하고 하나의 확정값으로 합치지 않는다.

## 7. 기준 예시

아래는 실제 초식이나 중간 동작을 복원한 자료가 아니라, 공간·지지·접촉을 구분하기 위한 **설명용 예시**다. 좌표와 허실은 예시의 가정이며 실제 예비식·攬雀尾 데이터로 재사용하지 않는다. 행 사이의 경로·동시성·접촉은 이 표만으로 알 수 없다.

| 장면 | 왼발 | 오른발 | 중심 C | 몸 방향 B |
| --- | --- | --- | --- | --- |
| 오른발이 지지하는 예시다. | `(0,0) ○`이다. | `(1,0) ●`이다. | 오른발 쪽 영역이다. | 기준 정면이다. |
| 빈 왼발이 앞에 놓인 예시다. | `(0,1) ○`이다. | `(1,0) ●`이다. | 오른발 쪽 영역이다. | 기준 정면이다. |
| 같은 발 배치에서 지지가 바뀐 예시다. | `(0,1) ●`이다. | `(1,0) ○`이다. | 왼발 쪽 영역이다. | 기준 정면이다. |

두 번째와 세 번째 행은 발 좌표가 같아도 지지 역할과 중심의 기록이 다를 수 있음을 보여준다. 접촉 근거가 없으므로 이 예시에는 Toe/Heel 기호를 붙이지 않는다. C의 영역을 정밀 좌표나 체중 비율로 바꾸지 않는다.

## 8. 웹앱 표시·데이터 원칙

화면은 같은 자세의 시작·중간·끝을 비교할 때 고정 축·배율·범위를 유지하는 것을 기본으로 한다. 화면 확대·이동은 저장 좌표와 분리한다. State에 픽셀 좌표를 넣거나, 매 화면에서 원점을 다시 잡아 실제 이동이 사라지게 하지 않는다.

기본 좌표판은 **C, 발 위치·허실·발끝 방향, 팔의 최종 구조 방향**을 우선 표시한다. B와 관절 연결 과정은 상세 데이터로 남긴다. C의 글자나 영역 표시를 겹치지 않게 옮기는 화면상 조정이 실제 중심 좌표 변화로 저장되어서는 안 된다.

좌표만 미등록이면 있는 설명은 보여준다. 발 위치는 있어도 허실·C가 미확인일 수 있으므로 화면 전체를 준비 중으로 막거나 해당 값을 자동으로 채우지 않는다. 미확인 지지는 ●/○와 구별해 표시하고, 구체적인 모양은 UI 단계에서 검증한다.

질적 방향·영역은 그 성격에 맞게 그리거나 글로 표시한다. 접촉·회전의 추론은 해설에 표시할 수 있지만 확인된 기호나 경로로 승격하지 않는다. 현재 보여주는 정보의 근거만 모으고 다른 자세의 고정 출처 문구를 재사용하지 않는다.

좌표와 화살표는 관계를 이해하기 위한 요약이다. 실제 발 간격·각도·지도와 다르면 숫자를 정답으로 삼지 않는다. 상대와 힘의 방향을 가정하는 그림은 수련자의 확인된 State와 별도의 해석 계층으로 다룬다.

## 9. 원칙 요약과 변경 기록

발의 공간 위치, 지지, 접촉, 중심, 몸 방향은 따로 기록하고 함께 읽는다. 현재 상태와 그 상태로 가는 변화, 변화에 대한 해석도 구분한다. 좌표 숫자 자체가 정답이 아니며, 빈 값을 채워 그럴듯하게 보이는 것보다 확인된 정보의 의미를 보존하는 일이 우선이다.

### 1.4에서 추가로 맞춘 사항

- 좌표판의 핵심을 C·발·팔의 최종 자세로 정하고, B와 관절 연결 과정은 상세 데이터로 분리했다.
- 팔 절대 방향 대신 몸 기준 `relativeDirection`을 저장하고, 화면의 빨간 화살표는 B와 합성해 계산하도록 정했다.
- 몸이 팔을 데리고 회전하는 경우와 팔 자체가 몸에 대해 움직이는 경우를 데이터에서 구분할 수 있게 했다.
- C의 점·영역을 좌표판 위에 직접 표시하되, 질적 영역을 정밀 좌표처럼 보이지 않게 구분한다.

### 1.3에서 맞춘 사항

- 기준 시점의 고정 축과 몸의 현재 좌우를 구분했다.
- 발 기준점을 접촉면 가운데에서 발 형태 중심의 평면 투영으로 바꾸고, 기존 값의 재검토를 명시했다.
- C의 점·영역·미확인과 발별 독립 지지 역할을 데이터 모델에 맞췄다.
- 접촉 상태와 들기·내리기 사건, B와 회전 ΔB를 분리했다.
- 시작 상태는 몸 정보만 참조하고 이전 사건이나 해설을 복제하지 않도록 했다.
- 기록 항목의 소유 위치와 필드별 근거·미확인을 정리하고, 예시를 실제 권가 자료와 명확히 구분했다.
- 방향 표의 열 수를 바로잡고, 저장 좌표와 화면 변환의 경계를 명시했다.

이번 완료 범위는 문서 정합성이다. 실행 가능한 전체 스키마·검증기, 예비식 데이터 변환, 렌더러와 시작 상태 탐색, 모바일·데스크톱 화면 검증은 별도로 진행한다. 사부님 실연과의 대조가 끝났다는 뜻도 아니다.
