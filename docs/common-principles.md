# eztaiji 공통원리 관리 규칙

이 문서는 공통 수련 원리(GlobalPrinciple)를 **어떻게 등록하고 연결할지** 정하는 관리 규칙이다.
실제 원리의 단일 원본은 `training/datasets/yijian.json`의 `principles`이며, 이 문서에 원리 본문을 다시 복사하지 않는다.

## 1. 공통원리의 역할

공통원리는 특정 자세 하나의 설명이 아니라 여러 동작에서 반복해서 확인하는 수련 원리다.

- 원리 본문은 `principles`에 한 번만 기록한다.
- 실제로 그 원리가 확인된 동작만 `Motion.principleIds[]`로 연결한다.
- 소개 페이지는 전체 `principles`를 보여준다.
- 동작 화면은 현재 동작의 `principleIds[]`만 보여준다.

따라서 “전역 원리”라는 이유만으로 모든 동작에 자동 연결하지 않는다.

## 2. 등록 기준

다음 조건을 만족할 때 공통원리 후보로 본다.

1. 한 동작의 손발 위치보다 더 넓은 움직임 원칙이다.
2. 다른 자세에서도 다시 확인할 가능성이 있다.
3. 사부님 설명, 문헌, 직접 관찰 등 근거를 특정할 수 있다.
4. 단순한 결과 자세가 아니라 “어떻게 움직이는가”를 설명한다.

반대로 특정 동작의 일회성 순서·좌표·손 모양은 공통원리로 올리지 않는다.

## 3. 근거와 해석을 분리한다

사부님에게 직접 들은 설명은 `basis: observation`으로 기록하고 실제 수련 메모를 근거로 연결한다.
문헌에 명시된 원리는 `basis: source`로 기록한다.
자료를 바탕으로 eztaiji가 풀어쓴 의미는 `basis: inference`로 구분한다.

전통 용어와의 대응도 자동으로 확정하지 않는다.
예를 들어 현장에서 “연결된 관절이 차례로 돌아간다”는 설명을 들었다고 해서, 사부님이 직접 그 명칭을 사용했거나 문헌 근거를 확인하지 않은 상태에서 곧바로 특정 전통 용어와 동일하다고 기록하지 않는다.

## 4. 원리 레코드

현재 GlobalPrinciple은 다음 필드를 사용한다.

- `id`: 안정된 내부 식별자
- `title`: 연습할 때 바로 알아볼 수 있는 짧은 제목
- `summary`: 한두 문장 핵심
- `explanation`: 원리의 작동 방식
- `example`: 확인된 대표 동작 예시(선택)

각 Claim에는 사실·관찰·추론의 종류와 근거를 함께 둔다.

## 5. 소개 페이지와 배포

`scripts/compile-data.mjs`는 동작 연결 여부와 상관없이 등록된 모든 `principles`를 배포 데이터에 포함한다.
소개 페이지는 이 배포 데이터에서 공통원리 목록을 읽어 렌더링한다.

따라서 새 공통원리를 추가할 때 소개 페이지의 문장을 따로 수정하지 않는다.
동작별 연결은 별도로 검토해 `principleIds[]`에 추가한다.

## 6. 검토 순서

새 원리를 넣을 때는 다음 순서로 확인한다.

1. 현장 기록 또는 문헌 Source를 먼저 만든다.
2. `principles`에 원리를 등록한다.
3. 확실히 연결되는 동작에만 `principleIds[]`를 붙인다.
4. 스키마와 참조 검사를 통과시킨다.
5. 소개 페이지의 전체 목록과 해당 동작 화면을 함께 확인한다.

실제 태극권 동작의 옳고 그름은 데이터 검증 통과만으로 확정하지 않는다. 현장에서는 사부님의 지도를 우선한다.
