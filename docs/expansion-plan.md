# eztaiji 확장 계획

- 목적: eztaiji를 단순한 자세 도해가 아니라, **좌표 → 신체 물리 → 음양 → 무술적 의미**를 함께 읽는 개인 수련 도구로 확장한다.
- 진행 원칙: 한 번에 많은 기능을 넣지 않고, 아래 항목을 하나씩 구현·검증한 뒤 체크한다.
- 기준: 실제 수련과 사부님의 지도를 우선하고, 자료에서 확인되지 않은 내용은 추론이나 예시임을 명확히 표시한다.

## 1. 시작 상태 개념 정의

목표: `0동작`이라는 표현 대신, 각 자세의 **시작 상태**를 명시한다.

### 원칙

- 시작 상태는 새로운 동작 번호가 아니다.
- 일반적으로 `이전 자세의 마지막 상태 = 다음 자세의 시작 상태`로 본다.
- 첫 자세인 預備式만 권가 시작 전의 자연스러운 초기 상태를 별도로 가진다.
- UI에는 `0동작`이 아니라 `시작 상태`라고 표시한다.
- 필요하면 설명에 `이전 자세 ○○의 마지막 상태`라고 덧붙인다.

### 체크

- [ ] `coordinate-system.md`에 시작 상태 정의를 추가한다.
- [ ] `routine-navigation.md`에 탐색 규칙을 추가한다.
- [ ] 첫 자세의 초기 상태를 어떻게 표현할지 확정한다.
- [ ] 이후 자세가 이전 자세의 마지막 상태를 참조하는 규칙을 확정한다.

## 2. 범용 동작·상태 데이터 구조 설계

목표: 預備式 전용 데이터 구조를 전체 64자세에 사용할 수 있는 구조로 바꾼다.

### 필요한 정보

각 프레임은 가능한 범위에서 다음을 가진다.

- 왼발·오른발 위치 `(x, y)`
- 각 발의 `● 實 / ○ 虛`
- 발끝 방향
- 발 접촉 상태: `Toe`, `Heel`, `Heel ↑`, `Heel ↓`
- 중심 `C`의 위치 또는 이동
- 몸 방향 `B`와 회전량 `ΔB`
- 동작 설명
- 왜 그렇게 움직이는지에 대한 원리
- 자기 점검 항목
- 음양 관계
- 전투 가정
- 근거와 확실도

### 개념 구조

```text
posture
  name
  startState
  motions[]

motion
  number
  title

  feet
    left
      x, y
      state
      direction
      contact
    right
      x, y
      state
      direction
      contact

  center
    x, y
    movement

  body
    direction
    delta

  instruction
  principle
  checks

  yinYang[]
  application

  evidence[]
```

### 체크

- [ ] 현재 `lx / lt / rt / cx / shi` 구조의 한계를 정리한다.
- [ ] 새 프레임 스키마를 문서로 정의한다.
- [ ] 모르는 값은 `null` 또는 미기록으로 남기는 규칙을 정한다.
- [ ] 관찰값과 추론값을 구분하는 필드를 정한다.
- [ ] 기존 預備式 4동작을 새 구조로 변환한다.
- [ ] 기존 화면이 새 구조에서도 동일하게 렌더링되는지 확인한다.

## 3. 음양 해석 원칙 만들기

목표: 음양을 단순한 좌우 대응이 아니라, 동작 안에서 실제로 변하는 관계로 설명한다.

### 원칙

- `왼쪽 = 陰 / 오른쪽 = 陽`처럼 고정하지 않는다.
- 해당 동작에서 실제로 드러나는 관계만 적는다.
- 모든 프레임에 억지로 음양 항목을 넣지 않는다.
- 하나의 프레임에 여러 음양 관계가 동시에 존재할 수 있다.

### 예시 관계

- `虛 ↔ 實`
- `開 ↔ 合`
- `進 ↔ 退`
- `收 ↔ 放`
- `상대의 進 ↔ 나의 化`
- `한쪽 공간을 비움 ↔ 다른 쪽 공간을 차지함`

### 체크

- [ ] 음양 해석 원칙을 별도 문서에 정의한다.
- [ ] 한 프레임에 여러 관계를 저장하는 형식을 정한다.
- [ ] 음양이 불분명한 경우 비워 두는 원칙을 명시한다.
- [ ] 預備式에서 실제로 유효한 음양 관계만 시험 입력한다.

## 4. 전투 가정 해석 원칙 만들기

목표: 동작을 고정된 공격·방어 기술로 단정하지 않고, 상대와의 힘 관계 속에서 이해한다.

### 기본 구조

```text
상황
상대가 어떤 힘을 주는가?

대응
그 힘에 대해 내 몸 전체가 어떻게 반응하는가?

결과
힘·중심·공간의 관계가 어떻게 바뀌는가?
```

### 원칙

- 손 모양만 보고 공격·방어를 단정하지 않는다.
- 독립된 전투 용법이 아니라 다음 동작을 위한 구조 형성일 수 있다.
- 한 프레임이 아니라 여러 동작 묶음 전체가 하나의 용법일 수 있다.
- 사부님 설명, 문헌, 외부 영상, 프로젝트 해석을 구분한다.

### 범위

- `motion`: 한 동작 자체에서 의미가 충분히 드러남.
- `group`: 左掤 등 여러 동작 묶음에 걸쳐 의미가 완성됨.
- `posture`: 한 자세 전체를 봐야 의미를 설명할 수 있음.

### 체크

- [ ] 전투 가정 작성 규칙을 문서화한다.
- [ ] `scope: motion / group / posture` 규칙을 확정한다.
- [ ] 독립 용법이 없는 동작의 표기 방식을 정한다.
- [ ] 출처와 추론을 구분하는 규칙을 확정한다.
- [ ] 預備式에는 억지 용법을 붙이지 않고 준비 구조로 설명 가능한지 검토한다.

## 6. 화면 구조 확장

목표: 현재의 간결한 모바일 연습 화면을 유지하면서, 원리·음양·전투 맥락을 함께 볼 수 있게 한다.

### 설명 영역 순서

1. **지금 어떻게 움직이나**
2. **왜 이렇게 움직일까?**
3. **여기서의 음양**
4. **전투 상황에서는**
5. **내 자세 확인**

### 표시 원칙

- 좌표판은 계속 고정한다.
- 긴 설명만 독립 스크롤한다.
- 해당 정보가 없으면 빈 카드나 억지 문장을 표시하지 않는다.
- 여러 동작에 걸친 설명은 범위를 명시한다.
- 출처가 필요한 해석은 근거를 접어 볼 수 있게 한다.

### 체크

- [ ] 시작 상태 UI를 추가한다.
- [ ] `여기서의 음양` 영역을 추가한다.
- [ ] `전투 상황에서는` 영역을 추가한다.
- [ ] `scope`가 group/posture일 때 범위를 표시한다.
- [ ] 작은 iPhone 세로 화면에서 스크롤과 버튼 동작을 확인한다.
- [ ] 태블릿·데스크톱 좌우 배치에서도 읽기 쉬운지 확인한다.
